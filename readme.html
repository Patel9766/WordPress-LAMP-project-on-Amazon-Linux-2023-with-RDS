🚀 AWS WordPress Deployment (LAMP Stack) This project demonstrates a production-ready WordPress installation on Amazon Web Services (AWS) using an EC2 instance and a managed RDS database. It highlights best practices in cloud security, database isolation, and version control. 🛠️ Tech Stack Cloud Provider: AWS (EC2, RDS, VPC) Operating System: Amazon Linux 2023 (Kernel 6.1) Web Server: Apache (httpd) Database: AWS RDS MySQL 8.0 Runtime: PHP 8.2+ Version Control: Git 🏗️ Architecture Features 1. Database Isolation The MySQL RDS instance is placed in a private sub-network. The Security Group is configured to only allow inbound traffic on Port 3306 from the specific EC2 Security Group ID, ensuring the database is not accessible from the public internet. 2. Modern AL2023 Implementation Unlike older Amazon Linux 2 guides, this project utilizes: dnf package management for optimized dependency handling. systemctl for robust service management. php-fpm integration for better performance. 3. Security & Governance Credential Protection: Sensitive files like wp-config.php are managed via .gitignore to prevent leaking RDS endpoints and passwords to GitHub. Permissions: Implemented strict Linux ownership (apache:apache) to allow WordPress auto-updates while maintaining a "Safe Directory" for Git operations. Hardening: Used unique Salt keys from the WordPress API for cookie encryption. 📖 Step-by-Step Implementation Phase 1: Environment Setup Bash # Update and Install Stack sudo dnf update -y sudo dnf install -y httpd mariadb105 php php-mysqli php-gd php-xml php-mbstring sudo systemctl enable --now httpd Phase 2: Database Provisioning Connected to the RDS endpoint and initialized the application schema: SQL CREATE DATABASE wordpressdbnew; CREATE USER 'wpuser'@'%' IDENTIFIED BY '********'; GRANT ALL PRIVILEGES ON wordpressdbnew.* TO 'wpuser'@'%'; Phase 3: WordPress Deployment Bash wget https://wordpress.org/latest.tar.gz tar -xzf latest.tar.gz # Configured wp-config.php with RDS Endpoints and Salts sudo cp -r wordpress/* /var/www/html/ sudo chown -R apache:apache /var/www/html 📊 Monitoring & Future Roadmap (Project 2) Logging: Configured Amazon CloudWatch Agent to push /var/log/httpd/access_log for centralized monitoring. High Availability: Ready for Auto Scaling by creating an AMI from this gold-standard instance. Elasticity: Planning to implement an Application Load Balancer (ALB) to distribute traffic across multiple Availability Zones. 👤 Author Arbaz Patel Cloud & DevOps Engineer Enthusiast Hyderabad, India
